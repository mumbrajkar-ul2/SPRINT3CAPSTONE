Challenge guide against Spine stages 0A–20

This page is the HTML copy of the challenge–spine mapping canvas. It compares the 16 core transformation challenges with Spine stages 0A, 0B, 0C, and 1 through 20. Stages 21–42 appear only to show where a missing requirement is required later. Source: Brownfield Repo Transformation Challenge Guide and AI FDE End-to-End Production Delivery Spine.

Stages 0A through 20 cover discovery and the build. The control challenges come later. Repo discovery and the behavioural baseline are the two challenges this range satisfies. Cost, AI boundaries, dependency scanning, and authorization start here as drafts or partial files. Identity, secrets, infrastructure as code, policy as code, CI/CD, observability, performance, failure engineering, security abuse cases, audit evidence, the production go or no-go, and the evidence pack are still open. Executable policy-as-code is also absent from the later stages.

Requirement coverage by challenge

Each bar is one challenge. The length of each color is the count of requirements. Match means a stage in 0A–20 requires the same work. Partial means a related file exists and the pass test is still open. No mapping means this range does not require that work. The three parts of a bar add up to the requirement count for that challenge.

How each challenge sits in this range

Covered means the pass test is met and every named output has a required file. Mostly covered means the pass test is met and at least one named output is still missing. Adjacent only means there is no full match and at most two related files. Partial means this range starts the work and the pass test is still open.
