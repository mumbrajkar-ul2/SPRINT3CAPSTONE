Governed telecom incident application

One case from an alarm storm to a person's decision. The model only recommends. A person decides. Nothing here changes a device.

How to read this page

Every number has a label next to it. REAL means the app counted it at the request. SIMULATED means the stub model made it up. EDUCATIONAL means a rule of thumb that is not a bill. PRECOMPUTED means it was copied from a stored report. This page shows no PRECOMPUTED number.

The role is a word this page sends in the X-User-Role header. Nothing proves who the caller is. The page calls it a claimed role.

Step one. Pick a storm and read its alarms

Role sent: operator (claimed role). Route: GET /alarms/storms/{storm_batch_id}.

Examples. STO-00002 has one flagged alarm, and its device gets a recommendation. STO-00005 has two alarms with the same dedupe key, and its device has a stale topology flag, so the recommendation is blocked. STO-00019 has two flagged alarms. STO-00001 names a device that has no device row.

Step two. Look up one device

Role sent: operator (claimed role). Route: GET /records/{id}. The two sensitive fields are left out for this role.

Step three. Ask for a recommendation

Role sent: operator (claimed role). Route: POST /ai/recommend/{id}. The model is a stub called local-sim-v1, so its text is SIMULATED. The outcome is never a command.

Step four. A person decides

Role sent: operator (claimed role). Route: POST /approvals/{id}. The server sets the approver. A yes gets an approval id. A no gets none. Neither one changes a device.

Step five. Read the audit chain

Role sent: admin (claimed role). Route: GET /audit/{correlation_id}. Only the admin role may read the audit log.

Service check

Route: GET /health. A live call, not a stored value.
