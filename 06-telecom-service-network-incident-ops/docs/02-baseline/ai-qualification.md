## What this file is

This file decides, for each capability, whether it needs a model, which kind, and how far it may go. The decision is made before the semantic layer, before any new architecture, and before the PRD.

Four words name how far a step may go. **Analyse** means read stored fields and show them. **Recommend** means show text a person can accept or reject. **Decide** means choose the outcome. **Execute** means carry out a change. These four stay separate (`Project_Intent.md` section 5.3).

**GenAI** means a language model writes new text from a prompt. **Agentic AI** means the model chooses tools and can take a step on its own. **Classical ML** means a model trained on past examples to predict a number or a class. **Rules**, **deterministic code**, and **workflow automation** return the same result for the same stored input.

A file path below is a **Verified Fact**. A map from a product name to a row is an **Inference**. A gap the repo does not fill is **Unknown**.

## Notes on the three GenAI picks

### Incident summary

The step writes a short account in sentences. The account has to follow the device, the alarms, and the incident words for that case. A rule can list those fields. Writing the account is the need a rule cannot meet: generation. The outcome is RECOMMEND_ONLY. The text is shown. The incident row stays as stored. The `noc_operator` is the reader. That desk job is PROPOSED. Owner: Team-Force.

The live function is `local-sim-v1`. It waits 0.01 seconds and pastes the first field into a fixed sentence (`ai_gateway.py` lines 9 and 13). That function is a stub. This row does not treat the stub as the GenAI step.

### Next-action recommendation

The sentence has to change when the mix of fields changes. A single stored sentence cannot do that. The need a rule cannot meet is reasoning over varied inputs, and the output is generated text. The outcome is HOLD_FOR_REVIEW. The `noc_operator` accepts or rejects the sentence before a change ticket exists. That desk job is PROPOSED. Owner: Team-Force.

A rule runs before the model. A missing id stops the call. The missing-id result stays deterministic (defect F01 is the current wrong return). A `stale_topology_flag` value of `true` stops the call. Those stops are BLOCK. What a blank `stale_topology_flag` should do is Unknown.

This row is GenAI with agency recommend. It is not agentic AI. An agent would choose tools and could change the network. The model stops at the sentence.

### Configuration suggestion

The step writes a suggested change for one device. Vendor, firmware, and alarms differ by row. The need a rule cannot meet is generation of that suggestion, and reasoning over those varied inputs. The outcome is HOLD_FOR_REVIEW. The `network_engineer` accepts or rejects the text before it enters a change plan. That desk job is PROPOSED. Owner: Team-Force. The model does not push the config. The push is the remediation execution row.

The mapping from the name Configuration Assistant to this row is an Inference. Confidence is Medium for that reason.
