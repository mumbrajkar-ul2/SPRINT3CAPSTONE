## Context

S07 recorded nine PRD gaps. Two of them change the PRD and one YAML formula. They must be closed before S08 hashes the tree.

**G-5.** The PRD O-4 list named four tests. S07 had to change four more tests that locked the old missing-id and 15-key behaviour. RQ-50 called `test_every_audit_row_has_every_required_field` "existing" and expected it to pass unchanged. **Verified Fact.** `docs/demo/evidence.md` section 5.

**G-7.** PRD section 8 told the page to show the share of audit rows with every key filled and the share of rows whose `prompt_hash` was seen before. No route in section 9 returns those numbers. The page shows neither. The script `docs/12-finops/metrics_from_audit.py` computes them over the whole log. The formula of `metric.audit_completeness` named `policy_result`, a key no audit row stores. **Verified Fact.** `semantic-layer/metrics.yaml` lines 90 to 107. The audit row stores `outcome` on a model call.

## Decision

### G-5

The PRD names eight tests to change, not four. The four extra tests are:

- `tests/test_characterization.py::test_legacy_missing_record_behavior_is_characterized` (now `test_missing_record_returns_nothing`). The loader returns `None` for a missing id.
- `tests/performance/test_load_once.py::test_empty_file_gives_the_error_body` (now `test_empty_file_returns_nothing`). The loader returns `None` on an empty file.
- `tests/performance/test_load_once.py::test_only_device_id_is_matched`. A site id or a hostname returns `None`. A device id still returns its row.
- `tests/observability/test_audit_schema.py::test_every_audit_row_has_every_required_field`. The row has 17 keys, and `final_action` is `none`.

RQ-50 now says the existing audit-key test expects 17 keys. The test status in `traceability.md` is "changed in S07, passed (2026-10-13)".

### G-7

The page does not show the share of rows with every key filled, or the share of rows whose `prompt_hash` was seen before. `metrics_from_audit.py` still computes both over the whole log. Both numbers are PRECOMPUTED.

The formula of `metric.audit_completeness` names `outcome` in place of `policy_result`. `outcome` is the audit key that holds `RECOMMEND_ONLY`, `HOLD_FOR_REVIEW` or `BLOCK` on a model-call row.

RQ-63 no longer cites `metric.audit_completeness` or `metric.repeated_prompt_share`. No new route is added.

### Version

The semantic layer goes from `1.2.0` to `1.2.1`. No id is added or removed. The glossary stays at 281 rows. The defined-id count stays 765. The PRD becomes v1.9. `traceability.md` becomes v1.10.
