## Prompt

```text
# Stage S04-05 — Infrastructure as code (Challenge 5)

## Objective
Half A: report the gaps between the written infrastructure and what a new team needs to rebuild the local environment. Half B: add one-command setup so a fresh clone runs the tests, and correct or document the Terraform gap.

## Scope
Include: `infra/terraform/main.tf`; venv and dependency steps; the Makefile; CI Python version; local and CI environments.
Exclude in Half A: any code change. Exclude in Half B: cloud resources, deployment to any real environment, CI stage changes (S04-07).

## Required analysis (Half A)
1. IaC gap report: `main.tf` writes a text file with a shared user; venv steps are implicit; no container; no environment split; no pinned Python version outside CI. Cite each.
2. Reproducible setup guide: the exact commands from a fresh clone to a passing `pytest -q`, on Windows and on Linux/macOS, using the tool versions recorded in S00.
3. Environment model: local and CI. What differs (Python version, env vars, paths). Where a value comes from in each.
4. Configuration ownership map: every config value, its file, its owner or Unknown, and whether it is a secret (link to S04-04).
5. Deployment dependency list: Python, pip packages with pins, optional OPA binary, optional Node for Playwright, each with the version observed and whether it is required for tests.
For each finding: finding, evidence, impact, risk, confidence, open questions.
STOP after Half A. Return the seven-item final response. Wait for "Half A accepted".

## Required work (Half B, after acceptance)
1. Add `scripts/bootstrap.ps1` and `scripts/bootstrap.sh` (or a `make setup` target that calls them): create venv, install requirements, run `pytest -q`.
2. Add a `Dockerfile` that installs requirements and runs the tests, so a fresh clone can run with one command.
3. Correct `infra/terraform/main.tf` to declare variables without a shared user and without writing credentials to a file, or leave it and write `docs/ADR/0002-terraform-gap.md` that says why it stays as a documented gap. Pick one and say which.
4. Run the bootstrap on this machine. Record the full output in `docs/05-iac/evidence.md`.

## Evidence rules
- Label every claim: Verified Fact, Inference, Assumption, Unknown.
- A Verified Fact names a file path, a command, or an observed version.
- The bootstrap run output is REAL.

## Constraints and guardrails
- Plain speech.
- No cloud account. No real deployment.
- Redact secrets.
- Each artifact starts with a header table: Stage, Date / version, Author, Status, Evidence sources, Assumptions, Unresolved issues, Residual risks.
```
